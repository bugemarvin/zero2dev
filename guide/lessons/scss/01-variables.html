What Sass is, and variables

A language that compiles to CSS, and the first thing it gives you: names for your values.

Install: what this track needs

Quick install

One command installs everything for this track. It skips what you already have.

Ubuntu, Debian, or Ubuntu inside WSL, from the zero2dev folder:

$ ./setup/install.sh --stack node

If something does not install, the script says why and offers to try again or to install it another way.

Windows, from an Administrator PowerShell in the setup folder (it installs WSL and Ubuntu first if needed):

powershell -ExecutionPolicy Bypass -File .\install.ps1 -Stacks node

macOS has no quick install script. Use the Homebrew commands below, or let Docker run what is missing.

Node.js and npm: by hand

Ubuntu, Debian, WSL:

$ curl -fsSL https://mise.run | sh
$ ~/.local/bin/mise use --global node@lts

macOS, with Homebrew:

$ brew install node

Check that it works:

$ node --version && npm --version

Or install nothing: with Docker running, the app runs JavaScript in the image node:22-slim (one download).

The sass packages come from npm, once: press Download packages on the Setup page, or run python3 check.py prefetch sass.

A web browser: you are using one now. Nothing to install.

This track builds on CSS.

The problem

A real stylesheet has thousands of lines. The same blue appears in forty places, the same media query in sixty, and the button styles are copied with small changes for every kind of button. CSS, for most of its history, had no way to say "this value has a name" or "this block is used again over there".

Sass is a language that adds those things. You write Sass, a program turns it into ordinary CSS, and the browser only ever sees CSS.

style.scss  --sass-->  style.css  -->  browser

Two syntaxes

Sass has two ways of writing. This track uses SCSS, the common one: it looks like CSS with extras, and every valid CSS file is already valid SCSS. You can rename a .css file to .scss and start from there.

Compiling

$ npm install --save-dev sass
$ npx sass style.scss style.css
$ npx sass --watch style.scss style.css       # compile again on every save

In a project built with Vite, Next.js or similar, you install sass, import a .scss file, and the build tool compiles it for you. In the exercises of this track, Run tests compiles your file.

Variables

A variable starts with $:

$brand: #1a73e8;
$radius: 8px;
$space: 16px;

.button {
  background-color: $brand;
  border-radius: $radius;
  padding: $space;
}

.card {
  border: 1px solid $brand;
  border-radius: $radius;
}

The compiled CSS has the values filled in:

.button {
  background-color: #1a73e8;
  border-radius: 8px;
  padding: 16px;
}

Change $brand in one place, compile, and every use follows.

Arithmetic

Sass can calculate with numbers that have units:

$space: 16px;

.card {
  padding: $space * 2;          // 32px
  margin-bottom: $space + 4px;  // 20px
}

Comments

// A line comment. It is NOT copied into the CSS.
/* A block comment. It is copied into the CSS. */

Sass variables and CSS custom properties

CSS now has its own variables, the custom properties from the CSS track: --brand: #1a73e8 and var(--brand). They are not the same thing.

Sass $variableCSS --property
existsonly while compilingin the browser, at run time
can change on the pagenoyes: with a class, a media query, JavaScript
can be used in Sass arithmetic, loops, functionsyesno

Use a custom property for anything that changes while the page is open, such as a light and a dark theme. Use a Sass variable for values that are fixed when you build: breakpoints, a spacing scale, things you calculate with. They combine well:

$brand: #1a73e8;

:root {
  --brand: #{$brand};
}

#{ } is interpolation: it puts a Sass value into a place where Sass would otherwise leave the text alone.

Scope

A variable declared at the top of the file is available everywhere below. One declared inside a rule exists only in that rule.

Common mistakes

  • Linking the .scss file from HTML. The browser cannot read it. Link the compiled .css.
  • Editing the compiled .css. The next compile overwrites it.
  • Expecting a Sass variable to change at run time.
  • The same value typed in many places in place of one variable.

Test yourself

A theme with Sass variables scss/01-variables

Write style.scss for the page in index.html.

Declare three variables at the top:

  • $brand is #1a73e8
  • $radius is 8px
  • $space is 16px

Then use them. Do not type the values again.

  • The h1 has the colour $brand.
  • .button has background-color: $brand, color: white, border-radius: $radius and padding: $space.
  • .card has a border of 1px solid $brand, border-radius: $radius, and a padding of twice $space: let Sass calculate it.

Edit the .scss file. Run tests compiles it to CSS and checks the page. Open preview shows the page with your compiled styles, and recompiles when you run or save.
